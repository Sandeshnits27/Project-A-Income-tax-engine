# Fire AI — Project A: Income-tax engine

This workspace contains a Python 3.10+ Project A implementation comparing a deterministic rules engine, a query-time Gemini implementation, and a static compiled-rules engine for Indian salary income. It covers FY 2024–25 and FY 2025–26, a plain-language parser, clarification handling, an audit breakdown, 220 structured cases, and 50 natural-language descriptions.

## Status: implementation prototype, not a validated tax product

The provided implementation guide requires official-source review and at least 30 comparisons with the Income Tax Department calculator. Those checks have **not** been completed here. Attempts to retrieve the Finance Act PDFs and official calculator source page were blocked; rule configuration therefore remains explicitly unverified. The 220 expected values come from a separate local reference implementation that uses the same unverified configuration, not from official-calculator validation. Do not use this engine to file a return or make a tax decision until an appropriately qualified reviewer verifies the law and the official-calculator cases.

The compiled configuration is a static local snapshot and was **not generated by Gemini** in this workspace. A Gemini rule-generation workflow is provided for future use with official source text. The query-time implementation receives the configured rule values and citations, not the full statutory text; that assignment requirement also remains pending.

## Run

From the workspace root, reproduce the unit-test results and the benchmark report:

```powershell
python -m project_a.reproduce
```

The command runs all local tests and rewrites `RESULTS_A.md` with current timings and outcomes. It does not call an external model. To opt in to query-time Gemini calls for the full 220-case suite (plus nine repeated requests), set `GEMINI_API_KEY` in the environment and run:

```powershell
$env:GEMINI_API_KEY = "<your-key>"
python -m project_a.reproduce --include-llm
```

Never put a real key in source control or `.env`; `.env.example` contains placeholders only. Free-tier eligibility, quotas, model availability, and pricing change over time and must be checked for the account before measuring or reporting costs. Query-time calculations send structured salary/tax facts to Google; do not send a person's data without appropriate consent and safeguards.

## CLI

Structured input:

```powershell
python -m project_a.main --json taxpayer.json --engine rules
python -m project_a.main --json taxpayer.json --engine compiled
python -m project_a.main --json taxpayer.json --engine llm
```

Plain-language input (returns clarification questions if required facts are unknown or contradictory):

```powershell
python -m project_a.main --text "FY 2025-26 salary 18 lakh, age 40" --financial-year FY_2025_26
```

Example complete structured input:

```json
{
  "financial_year": "FY_2025_26",
  "annual_salary": 1800000,
  "age": 40,
  "is_resident": true,
  "basic_salary": 900000,
  "eligible_da": 0,
  "hra_received": 0,
  "annual_rent": null,
  "city_category": null,
  "section_80c": 0,
  "section_80ccd_1b": 0,
  "section_80d_self_family": 0,
  "section_80d_parents": 0,
  "parents_ages": [],
  "home_loan_interest": 0,
  "home_loan_self_occupied": false,
  "home_loan_eligible": null
}
```

Use `null` for unknown facts; use `0` only when the taxpayer confirms the amount is zero. When HRA is positive, provide basic salary, eligible DA, rent, and city category. When home-loan interest is positive, explicitly confirm both self-occupied status and eligibility for the modeled Section 24(b) deduction. The user-provided 80C/80D amounts are treated as eligible amounts subject to statutory caps; this prototype does not independently verify each payment's legal eligibility.

## Layout

- `project_a/rules_engine/`: hand-coded calculation entry point.
- `project_a/llm_engine/`: opt-in Gemini calculation and token/latency capture.
- `project_a/compiled_engine/`: separate static tax-rule snapshots and an optional LLM rule-text compilation workflow.
- `project_a/parser/`: deterministic extraction, evidence snippets, contradiction detection, and clarification state.
- `project_a/config/`: versioned, unverified FY-specific tax parameters and source status.
- `project_a/configuration.py`: SHA-256 integrity checks for versioned rule configurations.
- `project_a/tests/`: independent local reference routine, frozen test cases, and unit tests.
- `project_a/data/natural_language_cases.json`: 50 parser inputs and frozen initial expected extraction/clarification snapshots.
- `project_a/benchmarks/`: same-case accuracy, repeatability, latency, parser measurements, and report generation.
- `RESULTS_A.md`, `DECISION_MATRIX.md`, `AI_USAGE.md`: assignment reports.

The project scope excludes capital gains, business income, and other income heads. It also excludes eligibility exceptions not represented in the input schema, income taxed at special rates, TDS/refund calculations, and filing advice. The workspace is not a private GitHub repository and has not been shared with the hiring team.

The LLM rule-generation helper writes a validated `*_candidate.json` file to a staging directory. A candidate is not loaded by the calculator; a human must compare it to official law, approve it, place it in the compiled-rules directory, and regenerate its checksum.
