# Project A — Decision matrix

These are provisional choices for the prototype, not claims that one implementation has won legally or operationally. Local accuracy is measured only against the separate reference routine using the same unverified configuration. See the run-specific figures in [RESULTS_A.md](./RESULTS_A.md). Official calculator comparisons and Gemini measurements remain pending unless explicitly reported by a run.

| Component / check | Choice | Measurement or evidence | Decision / limitation |
|---|---|---|---|
| Slab arithmetic | Rule | Rules engine compared on the same 220 frozen cases against the local reference; exact figures are generated in RESULTS_A.md. | Use deterministic arithmetic. Local agreement is not a legal correctness proof. |
| HRA and deductions | Rule | Per-rule tests plus the shared 220-case suite; no official calculator confirmation. | Keep eligibility inputs explicit and calculations auditable; review missing statutory eligibility conditions. |
| Section 87A and residency | Rule | Boundary-oriented local cases; a targeted resident/non-resident test. | Rebate gate and threshold math must remain versioned and verified against the Acts. |
| Surcharge, marginal relief, cess and rounding | Rule | Same-case oracle comparison, including high-income boundary fixtures; no official-source validation. | Deterministic sequence and line items; do not release before statutory review. |
| Financial-year configuration | Rule | Two year-specific files; FY 2024–25 regression inputs remain in the common suite. | Immutable, reviewed configuration is safer than prompt-only updates. |
| Natural-language field extraction | Rule (prototype) | 50 fixed English/Hinglish/incomplete/contradictory inputs; parser snapshot test and measured local latency. | Clarify when a fact is missing or ambiguous; extraction is limited regex-based coverage, not a general language model. |
| Input validation and clarification | Rule | Tests verify `null` remains distinct from explicit zero and conflicts block a tax-ready result. | Reject invalid or incomplete inputs rather than defaulting to zero. |
| Query-time tax computation | LLM (experimental) | Requires explicit opt-in and Gemini credentials; if not run, accuracy, repeatability, latency and tokens remain unmeasured. | Never treat generated values as authoritative; compare against validated deterministic outputs before use. |
| One-time rule conversion | Hybrid (LLM generation + validation) | Generator exists; static configs in this workspace were not generated by Gemini and no generation/review duration was recorded. | Generated config must pass schema, statutory and regression review before promotion. |
| Compiled execution | Rule | Separate static snapshots run on the common local suite; they are not independently validated Finance Act extractions. | Execution can avoid per-request model calls; maintain a reviewed provenance trail. |
| Regime choice and explanation | Rule | Computed comparison and structured audit lines are deterministic; user-facing legal explanation not validated. | Derive the recommendation only from verified totals; avoid unsupported legal prose. |
| Cost and scale | Hybrid (provisional) | Local model-free paths make no API calls; no production load test or account-specific Gemini billing data was collected. | Route only language tasks to an LLM; scale/cost claims remain unmeasured. |
