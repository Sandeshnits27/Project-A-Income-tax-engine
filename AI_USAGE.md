# AI usage note

- **Copilot coding assistant:** used to read the supplied PDFs, structure the Python modules, draft the rules-engine/parser/benchmark implementation, and add tests and documentation.
- **Local Python standard library:** used to extract the provided PDFs with `pypdf`, run the implementation, produce frozen fixtures, execute `unittest`, and measure local timings.
- **Gemini API:** no request was made while creating this workspace. Query-time and one-time compiled-rule workflows are optional and require a user-supplied `GEMINI_API_KEY`; the saved compiled snapshots were not generated by an LLM.
- **Official tax sources/calculator:** the official portals were identified as the required source locations. Attempts to retrieve the Finance Act PDFs and official calculator page were blocked in this environment, so no official comparison is claimed.

One AI-drafted parser pass interpreted the Hinglish amount `20 hazaar` as a bare ₹20 and did not convert monthly rent to annual rent reliably. Reviewing the natural-language corpus exposed the issue; the parser was corrected to recognize `hazaar` and monthly wording, and a regression test now expects ₹20,000 per month to normalize to ₹2,40,000 per year.

Another review caught an AI-drafted configuration that applied the old regime's 37% top surcharge to the FY 2024–25 new regime. The new-regime 25% surcharge cap is now represented separately and covered for both financial years by a regression test. This is a code-level correction, not an official-source validation; that remains pending.

The frozen tax expected values are produced by a separate local reference implementation, but they share the same unverified tax configuration and are not official legal validation. The parser's expected outputs are frozen initial snapshots; they should be reviewed independently rather than treated as human-verified annotations.
